# AI Usage Disclosure & Interaction Summary

## 1. Process Overview
This project was developed using an AI-assisted workflow. The AI (Gemini 1.5) served as a Lead Architect and Senior Developer, while I acted as the Product Owner and System Integrator. 

Due to the project's complexity and a session reset, the following summary outlines the logic and queries used to build the system from scratch.

## 2. Methodology: From Prompt to Product
The development was divided into four main interaction phases:

### Phase A: Architecture & Project Scaffolding
- **Objective**: Create a professional, scalable .NET structure.
- **AI's Role**: Guided the creation of a Multi-Project Solution (.slnx) instead of a flat project.
- **Key Interaction**: "Design a layered architecture for a C# automation project that includes an API wrapper, a Domain layer for logic, and a separate Unit Test project."

### Phase B: Core Automation (Playwright)
- **Objective**: Implement the Page Object Model (POM) for SauceDemo.
- **AI's Role**: Wrote the automation services, including explicit waits and robust selectors to handle the dynamic DOM.
- **Key Interaction**: "Create a Playwright service in C# that logs in, sorts items by price, and finds the cheapest product while handling currency symbols and string-to-decimal conversion."

### Phase C: Unit Testing & Logic Validation
- **Objective**: Ensure 100% accuracy in price calculations.
- **AI's Role**: Authored 8 comprehensive unit tests using MSUnit.
- **Key Interaction**: "Generate unit tests to verify my 'PriceNormalizer' class. Cover edge cases like missing '$' signs, null values, and different decimal formats."

### Phase D: Infrastructure & Debugging (The "Linux Fix")
- **Objective**: Solve environment-specific crashes.
- **AI's Role**: Identified the `AddressInUseException` and provided the programmatic fix for dynamic port allocation.
- **Key Interaction**: "My .NET API crashes on Linux because port 5199 is busy. How can I modify launchSettings.json or Program.cs to use a fallback port automatically?"

## 3. Human Oversight & Validation
Every line of code generated by the AI was:
1. **Reviewed**: To ensure it follows C# naming conventions and clean code principles.
2. **Compiled**: Verified using `dotnet build`.
3. **Tested**: Verified using `dotnet test` (All 8 tests passed).
4. **Environment-Tested**: Manually debugged on a Linux (Ubuntu) machine.

## 4. Conclusion
The AI provided the technical building blocks and solved complex infrastructure bugs, while the human developer defined the business requirements, integrated the components, and performed final quality assurance.
